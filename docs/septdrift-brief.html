SEPTDRIFT · ONE-PAGE BRIEF · 2026-09-22 · WEEK ONE, DAY 5

The on-device model changes every September. Septdrift tells you what your feature lost.

A macOS command-line harness that runs declared cases against Apple's Foundation Models, records every answer as a hash-chained receipt, and diffs two recordings. A check that passed before and fails now is a flip, and a flip is exit code 1.

Platform macOS 27.0+, Swift 6, Command Line Tools only Model Apple on-device 3B via FoundationModels Repo github.com/frankbesch/septdrift Status week-one build, 116 tests, day 4 pending a second Mac

Why

Behavior drifts under you, silently.

A feature built on the on-device model ships against one model build. Each macOS release replaces that model. Nothing in the app changes, yet answers, timings, guardrail behavior, and structured output can all move.

Today the only signal is a user report. Septdrift turns "it used to work" into a recording from before, a recording from after, and a diff that names the check, the chip, the OS build, and the model asset ID on both sides.

The first finding came on day 3: asked what an AFE is in oil and gas, the 3B model answered with a different invented expansion on every run. With the definition supplied in context and asked for back, it passed 3 of 3.

How

Declare, record, verify, diff.

  • Declare cases in YAML: prompt, optional instructions and context, text or JSON format with an ordered schema, generation options, repeat count, and one or more checks.
  • Record each response as a receipt: content, wall time, token usage, model asset IDs, typed error, and the outcome of every check. Records chain by SHA-256 over canonical bytes.
  • Verify a recording offline: every hash, the chain, sequence contiguity, the trailer count, and that every expected (case, rep) appears exactly once.
  • Diff two recordings by case ID and check identity. Pass rate per side, then a class: flip, degrade, fix, or unchanged. Medians and error-kind counts per side.
  • Fixture backend replays canned answers with no model call, so the whole path runs in CI.

What

Four commands, five exit codes.

runRun every case against system or fixture; write one recording. Exits 0 when it completes; the diff judges.
verifyRecompute the chain. Prints OK n results or the first failure with its seq.
diffScore B against A. --json, --fail-on-fix, --allow-request-drift.
casesValidate a file or directory and list what it declares.

exit 0 ok · 1 flips · 2 model unavailable · 3 validation · 4 I/O or incompatible inputs

Checks: contains, not_contains, regex, json_field_equals (typed by schema kind), max_wall_ms, max_output_tokens, expect_error.

Architecture

ModuleOwns
Case, CaseLoaderYAML/JSON → [Case]; every validation rule fails the run before any model call (exit 3).
Backendprotocol Backend { respond(to:rep:) async throws -> Result }. SystemBackend wraps LanguageModelSession, one fresh session per (case, rep), maps LanguageModelError to six typed kinds. FixtureBackend replays JSONL keyed by (caseID, rep).
Checks(Check, Case, Result) → {pass, reason}. Error short-circuits every check except expect_error.
Canonical, RecorderCanonical JSON bytes (sorted keys, no whitespace, integral numbers as ints, explicit nulls). Header before the first call, trailer after the last: a crash leaves the file incomplete by construction. Exclusive create; verify checks runID on every record.
DiffPairs by caseID; rate per (case, check identity) per side; flip / degrade / fix / unchanged; request-hash drift excluded when allowed; text and JSON renderings carry the same fields.
CLIswift-argument-parser glue only. Dependencies: Yams, swift-argument-parser. No Xcode project, no app bundle.

One receipt, shortened

// result record, M4, macOS 27.0 (26A428), live {"schema":"receipt/0.2","type":"result","seq":1, "runID":"a47fc76b-…","ts":"2026-09-22T08:28:09Z", "caseID":"afe-no-context","rep":0, "requestSHA256":"…","assetIDs":["com.apple.fm.language.instruct_3b…"], "content":"An AFE, or Accommodation Fee Estimate, …", "wallMs":1421,"tokens":{"in":76,"cached":0,"out":37,"reasoning":0}, "error":null,"errorDetail":null, "checks":[ {"name":"contains","arg":"Authorization for Expenditure","pass":false,"reason":"not found"}, {"name":"max_wall_ms","arg":"3000","pass":true,"reason":null}], "prev":"e76eddf9…","sha256":"3b1c…"}

Every field that can move between OS builds is on the record: the model asset IDs, the host's chip and build, timings, tokens, and the outcome of each declared check. The hash covers the canonical bytes with sha256 blanked; prev is the previous record's hash value. Ten fixed hash vectors ship in the tests so a second implementation can match byte for byte.

Limitation, stated. The chain is unsigned. verify proves a file is internally consistent, not where it came from. Signing is a non-goal in v0.3.

Guarantees the design leans on

  • Check identity is (name, argument); a scorecard row is stable across runs and machines.
  • Repeats give rates, not booleans: 2/3 vs 3/3 is a degrade, 3/3 vs 2/3 is a flip.
  • Diff refuses incompatible inputs (different casesSHA256) unless request drift is allowed, and then lists the changed requests instead of scoring them.
  • Tests never call the model. Live runs are receipts, not tests.
