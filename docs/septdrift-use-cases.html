01 · OS-UPDATE REGRESSION GATE

Know what the update took before your users do.

Why

Apple states the model changes when a person updates to macOS 27 and tells developers to re-test their prompts. Nothing in your app changed, but answers, formats, and timings can all move. The only signal today is a user report.

How

Record the case file on the current build before updating. Update, or point the run at a beta machine. Record again. Diff A against B. A check at 100% on A and below 100% on B is a flip.

What

A scorecard with one row per (case, check), the pass rate on each side, and a class. Headers carry both OS builds and the model asset IDs, so the change is attributed to the model, not guessed. Exit 1 fails the pipeline.

02 · BACKEND-SWAP DIFF

Pick the engine with evidence, then keep it honest.

Why

macOS 27 puts on-device, Private Cloud Compute, and third-party frontier models behind one session API. The choice is now a config flag, and a flag is easy to flip without measuring. Cost, latency, and refusal behavior differ by engine for the same prompt.

How

Run the case file once per backend. Diff any pair. The header names the backend; the scorecard carries pass rates and per-side medians of wall time and output tokens. Request drift is refused unless allowed, so an engine that needs a different prompt is caught, not hidden.

What

A per-check comparison across engines, a medians line per side, and an error-kind count per side. Enough to choose, and enough to re-run after either engine updates.

Capabilities to nail it

03 · DOMAIN-KNOWLEDGE TRIAGE BEFORE RAG

Find out which words the model does not know before you build retrieval.

Why

A 3B distilled model has no room for a trade's vocabulary. It answers fluently and wrong. Retrieval is not optional, but nobody knows which terms need it until they measure. Guessing over-builds the RAG layer or ships a hallucination.

How

For each domain term, declare a pair: the bare question, and the same question with the definition in `context` and a prompt that asks for the term back. Run with `repeat: 10`. The pair's pass rates say whether the term must ride in the prompt.

What

A ranked list of terms by bare-prompt failure rate, each with a passing with-context prompt already written. Every passing prompt is a declared check, so the next model update tells you whether the fix still holds.

04 · LORA ADAPTER ACCEPTANCE

Accept an adapter the way you accept a build.

Why

Apple's adapter toolkit trains LoRA adapters offline on a Mac. An adapter is tied to a base model version; when the OS replaces the base, the adapter's behavior can move or the adapter can stop loading. Teams need the gain measured once and the survival measured at every update.

How

Record base and base-plus-adapter on the same build; diff for gain and for regressions on cases the adapter was not trained for. After the update, record the adapter again and diff against its own pre-update recording.

What

Two scorecards. The first justifies shipping the adapter. The second is the retrain trigger. Both name the adapter identifier alongside the base asset IDs.

05 · FLEET VARIANCE ACROSS CHIPS

Separate the model from the machine.

Why

A feature tested on the developer's M4 ships to M1 laptops in the field. Quantization and scheduling differ by chip; sampling adds noise. A support ticket cannot tell you which one bit. Enterprise Mac fleets on mixed hardware need the attribution, not the anecdote.

How

Ship the tarball. Each Mac runs `mini-run.sh`, which builds, runs, verifies, and leaves one stamped recording on the Desktop. Collect the files and diff any pair. Read the two `side` lines before the table.

What

A diff whose header names chip, OS build, and asset IDs on both sides, and a rule for reading it: equal asset IDs means the flip is chip or sampling; different IDs means the model changed.

06 · TOOL-CALLING AND STRUCTURED-OUTPUT CONTRACTS

Make the schema and the tool call a contract the update cannot break silently.

Why

The 27.0 model is rebuilt with better tool calling, and tool-call formatting changed with it. Apps that parse the model's output, or dispatch on its tool calls, break in ways that unit tests of the app cannot see because the model is not in the test.

How

Declare `format: json` with an ordered schema and one `json_field_equals` per load-bearing field. For tools, declare the tool set and the expected call with its arguments. Record; diff after each update.

What

A row per field and per expected call. A type change, a renamed field, or a missed tool call is a flip with a reason string, for example `expected 3 got "3"`.

07 · GUARDRAIL AND REFUSAL DRIFT

Catch the prompt that starts tripping the guardrail.

Why

Each model update retrains safety behavior. A prompt that was fine can begin returning a guardrail error, or a refusal in prose, or an unsupported-language error for a locale you ship. These arrive as support tickets with no reproduction.

How

Run the prompts that matter with `repeat: 10`. Errors are typed on the record from `LanguageModelError`. Declare `expect_error` where a refusal is correct and a no-error expectation where it is not. Diff after the update.

What

Error-kind counts per side, a rate per case, and a flip when a prompt starts failing. For refusals in prose, a `not_contains` check on the phrasing the model uses.

08 · TOKEN AND LATENCY BUDGETS

Budget the update, not just its accuracy.

Why

Tokenization and token counts moved with the 27.0 model, and Apple warns against hard-coded context numbers. A feature with a latency budget or a context budget can regress with every answer still correct. Accuracy evals do not see it.

How

Declare `max_wall_ms` and `max_output_tokens` on the cases that carry a budget. Use `repeat` so a rate absorbs the noise. Record before and after; the medians per side show the shift, the rate shows the breach.

What

Per-side medians of wall time and output tokens over non-error results, and a flip when a budget check drops below 100%. Cached and reasoning tokens are on every record for the next question.

Capabilities to nail it

CapabilityWhy it matters hereStatus
`max_wall_ms`, `max_output_tokens`, four token counts per record, medians per sideThe budget checks exist.HAVE
Numeric tolerances: `max_wall_ms: {p50: 1500, p95: 3000}`A single ceiling is either too loose or noisy; percentiles match how budgets are written.WEEK 2

09 · CI FOR FOUNDATION MODELS FEATURES

Put the model's contract in the pipeline without putting the model in the pipeline.

Why

CI runners rarely have Apple Intelligence. Teams either skip model tests or run flaky live ones. Frontier practice is now continuous testing on every model update before real work moves to it; Mac developers have no native shape for that.

How

Commit the case file and a fixture recording. CI runs the fixture backend, verifies, and diffs against the committed baseline; a change in what the app sends (prompt, schema, options) shows as request drift. A Mac lane records live and promotes the recording to the next fixture.

What

A merge gate that fails when the app changes the contract, and a live receipt stream that fails when the model does. The two lanes answer different questions on purpose.

10 · AUDITABLE RECEIPTS FOR REGULATED SHIPPING

Ship a model feature with evidence, not logs.

Why

Regulated teams need to show what the model did at release time, on what build, with what results, and that the record was not edited after the fact. Application logs do not carry the model build or a tamper check. Every septdrift record does.

How

Record at release, keep the file with the build artifacts, and verify it in the release checklist. Diff each subsequent OS build against it. Add a signature over the trailer hash when signing lands.

What

A file an auditor can verify offline with one command and no model access: prompts, answers, checks, timings, model asset IDs, host, and a chain that names the first altered record if any.

Capabilities to nail it

CapabilityWhy it matters hereStatus
Canonical bytes, chained SHA-256, `verify` offline, hash vectors for a second implementationConsistency is provable now, by anyone.HAVE
Strict receipt typing; runID on every record; exclusive createVerify must refuse a plausible forgery, not just a broken chain.WEEK 2
Signature over the tail hash with a Secure Enclave or developer keyOrigin. The one capability this market cannot do without.NEW
Redaction mode: content hashed, not stored, with the check outcomes keptSome prompts cannot leave the machine; the receipt still has to.NEW
